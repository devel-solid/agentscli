# Publication

Use this reference when publishing or reconciling a hub content release. Publication must already be requested. Native Git owns authentication and hosting. Configure a remote with native Git if missing; the helper diagnoses a missing or ambiguous remote/branch instead of choosing a provider. It does not create a hosted repository or publish npm packages.

Assess the highest semantic impact: internal-only edits and corrections are patch, compatible resource additions are minor, incompatible rules and resource removal/rename or new required dependencies are major. The first release is 1.0.0. An explicit valid user version overrides this derivation. The private helper accepts that assessment with --bump and derives a candidate from published history, independently of the generator package version.

Run the plan mode first for concrete content version, tag, destination, and scoped paths. Plan reads current files, native status/history, and remote refs without changing files, the index, or refs. Use --path repeatedly when the requested publication scope excludes other hub edits. All hub paths are eligible by default; unrelated paths and staging remain outside the scoped commit. Partially staged selected files block until their intended content is reconciled, avoiding silent inclusion of unrequested hunks.

The helper validates manifest, safe complete trees, convention self-containment links, standard skill metadata, reserved identities, and explicit same-hub dependency closure before publication. Separately review semantic compatibility, activation, and whether a procedure belongs in a skill. Inspection never executes shared skill code.

Publish updates the content manifest, makes a scoped native Git commit, creates an immutable lightweight v-prefixed tag, pushes the candidate commit to the intended branch and the tag, and verifies both refs. A matching already-published candidate with no content changes is a no-op. Published tag manifests must agree with their versions. Divergence, conflicting immutable identities, or unavailable required history blocks instead of guessing or forcing. If the helper reports missing native objects, reconcile/fetch through native Git before rerunning; plan never fetches.

On partial or lost responses, retain the exact candidate version and commit in the result. Inspect local and remote refs. Matching branch/tag delivery counts as complete; one matching ref alone remains partial. Retry the same helper invocation and explicit scope: its manifest/HEAD/tag inspection reuses the unfinished candidate and only completes missing delivery. Do not select another bump, retag, force a push, or invent a journal. If the worktree changed after an unfinished release, reconcile that candidate before starting another release. Report concrete completed and pending effects, never claim rollback or success before both refs are verified.
