# Resource hub

This independent Git repository shares explicitly selected conventions and complete skill trees. Use any native Git host, public or private. Configure the remote with native Git; no vendor service or npm publication is required.

Author internal rules in `docs/conventions/`, discovery in `AGENTS.md`, shared templates in `shared/conventions/`, and shared skill trees in `shared/skills/`. Operational skills under `.agents/skills/` maintain the hub and are not shared resources. Each authoring area has its own operational skill. Ask to publish hub changes to use agentscli-hub-publish: the agent assesses impact and the included helper selects and verifies the content release. Ordinary publication does not ask you to choose a version.

Shared conventions begin with YAML containing only `trigger`, followed by one H1 and self-contained Markdown. Their path relative to `shared/conventions/` without `.tpl.md` is the convention identity. Shared skills are direct-child directories under `shared/skills/`, identified by directory name, and use standard `SKILL.md`; optional `metadata.agentscli: agentscli-skill.yml` points to one sibling general YAML mapping. Its optional `requires` list contains only skill id/source mappings, with source hub for shared dependencies. Each skill includes its own operation instructions and bundled support; conventions are not dependencies. Neither conventions nor skills link directly to other resources; skills discover required skills by identity. Skills without additional configuration need no extra file.

The manifest starts with schemaVersion 1 and content version 1.0.0. Content tags use `v1.0.0`, independently of the CLI package version. Consumers pin one exact commit and select only the resources they need; all declared dependencies must also be explicitly selected.

Run `agentscli-hub apply <directory>` again to update the five managed operational skill trees and this README. Their edits are disposable and obsolete managed files are removed. Authored content, intentional authored deletions, manifest version, Git policy, remotes, refs, staging, and unrelated files are preserved. `--dry-run` previews the same plan without writes. An interrupted apply reports completed and pending effects; retry the same command.

An interrupted first creation can resume when native Git remains unborn, has no refs, staging or remotes, and the non-Git files are an exact subset of the initial scaffold. Changed, unrelated, or unsafe content requires explicit reconciliation. The manifest is written last; after identification, repeat apply always preserves authored deletions.
