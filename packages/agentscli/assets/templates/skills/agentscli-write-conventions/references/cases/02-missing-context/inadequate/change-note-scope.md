# Change note scope

Record relevant changes in the change notes. Focus on what changed and why it matters, using concise language that makes the result easy to understand.

Public release notes should emphasize useful information and avoid unnecessary implementation detail. Keep the internal change log up to date with technical context that helps maintainers understand the work.

Describe fixes as well as new capabilities. Keep each entry focused on one change, and avoid copying a long development discussion into either log.
