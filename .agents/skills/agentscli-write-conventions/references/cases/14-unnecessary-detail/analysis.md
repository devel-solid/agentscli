# Detail beyond the decision

## Hypothetical context

A fictional project's text snapshot fixtures use the lowercase `.snap` extension. That is the entire agreement being documented. The request establishes no basename pattern, directory layout, snapshot framework, update procedure, or requirement for other kinds of fixtures. The intended readers already understand file extensions.

This narrow context is deliberate: a short corrected document is justified by a simple established decision, rather than by an author's unsupported claim that a complex rule is obvious.

Compare the complete [inadequate convention](inadequate/snapshot-extensions.md) and [corrected convention](corrected/snapshot-extensions.md).

## What remained wrong

The inadequate draft states the correct extension but surrounds it with explanations of filenames, a repeated comparison, and a closing restatement. None changes the reader's choice. Its polished sections can make the repetition look like thorough coverage even though the decision is already complete in the first paragraph.

There is no remaining uncertainty about the extension after that paragraph. Adding more examples cannot supply a missing distinction when no such distinction exists in the established agreement.

## What changed and why

The correction keeps the file contract, precise trigger, and one sentence containing the full agreement. It removes the tutorial and redundant examples without widening the rule to all fixtures or adding a naming policy.

A single sentence is sufficient because the fixture category, exact suffix, and case are explicit. It would not be sufficient for a rule that also governed snapshot contents or update behavior; those choices are absent from this hypothetical agreement.

**Transferable concept:** Match detail to the unresolved decision. Concision is demonstrated by retaining everything needed for application, not by declaring every technical rule self-explanatory.
