# Release the CLI package

Discover this repository's single public package at its root through current package metadata and project instructions. Run this skill's [candidate checker](scripts/check.mjs) from its own skill directory with `node scripts/check.mjs --repo-root <root> --package agentscli` for concrete candidate checks. Reject private roots, workspace orchestration, and installed package targets.

When subagents are available and permitted, delegate substantial independent read-only checks, such as compatibility assessment or archive inventory review. Give each reviewer this skill and the exact candidate diff or commit, package/version, and relevant artifact with its integrity when available. Keep version and lockfile writes, builds, resource refreshes, Git mutations, publication, and host installation with one coordinating agent; a small release may need no delegation. Reconcile findings before the corresponding release gate and repeat affected reviews if candidate inputs change. For example, an archive review applies to the inspected tarball, not a later repack with the same version.

Derive package identity/version, executable, registry, Git remote, and tag from actual metadata and current local/remote/registry state. Tags use agentscli-v<version>. Preserve immutable identities, native authentication, unrelated work, and staging. Never collect/print tokens, rewrite history, force-push, or replace published identities.

Assess completed impact and choose an unused semantic version. Major zero means beta; production starts at 1.0.0. Beta contract changes do not require promotion to production. Account for public contract impact and managed replacement. Prepare metadata with native `pnpm version <version> --no-git-tag-version --no-git-checks` at the verified package root after identifying the authorized pending diff. The second flag permits preparing metadata before committing that diff; it does not disable the later explicit commit, tag, and archive checks. Keep dependency pins and the pnpm lockfile graph unchanged unless the release includes an authorized dependency change.

After completing changes and setting the package version, run `pnpm run dogfood` from the verified root. It builds canonical package sources, runs the compiled checkout CLI's init to refresh this repository's installed skills and generator provenance to the new version, and synchronizes the index through the build skill's canonical support. This preparation does not require an installed host CLI or a published candidate version. Never hand-edit those managed resources. Run focused units and `pnpm run check`, including the read-only resource and index checks. Rebuild, refresh, and repeat the relevant checks and archive inspection whenever candidate inputs change.

Only after those checks pass, inspect `pnpm pack --dry-run --ignore-scripts --json` and create an actual archive with `pnpm pack --ignore-scripts --json --out <ignored-tarball-path>`. Use the exact pnpm version from `packageManager`, the publication workflow's exact Node version, and its packing configuration for both the local candidate and CI reconstruction. Use `pnpm ci` for a clean frozen installation. Pack only after the verified build, with scripts disabled in both places. Accept pnpm's default manifest transformation: it removes package-manager metadata and publication hooks such as `prepack`. The checker permits those removals while still comparing ordinary and install-time scripts. Compute SHA-512 from the actual archive and compare it with the pack JSON integrity; a dry run has no archive integrity. Check each archive using this skill's checker with `--archive <tarball>`. Verify identity/version/license/bin, the exact runtime and resource inventory, three complete skill closures, actual generator stamps, and README/license. Keep the repository's publication skill out of the package.

Discover the repository's Publish agentscli workflow from its versioned GitHub Actions configuration. Publishing uses npm Trusted Publishing for the actual package, repository, and workflow filename, with direct publishing enabled. Use the browser for the one-time account setup when needed; personal authentication remains with the user. Do not collect an npm token or fall back to a local publish when trust configuration is missing. Existing native Git authentication remains sufficient for source delivery.

Present exact reviewed source commit or pending diff, versions/tags, destinations, tarballs, SHA-512 integrity, and the final host installation target and exact package version before external delivery. Reuse existing scoped authorization; request only missing authorization or concrete account/destination information. Local readiness is not publication.

Within authorization, commit reviewed source and create the immutable unused annotated release tag. Include exactly one `Integrity: <reviewed-sha512-integrity>` line in its annotation. Verify npm trust configuration before pushing the tag: pushing an agentscli-vX.Y.Z tag automatically starts Publish agentscli for that tagged commit. Ordinary branch pushes do not start publication, and there is no manual dispatch. The workflow derives the version from the tag, requires it to match package metadata, reads the reviewed integrity from the annotation, repeats the shared checks, builds and inspects an archive, and refuses to publish unless its bytes match that integrity. It publishes that inspected archive with public access using `pnpm publish <tarball> --access public --ignore-scripts --no-git-checks --publish-wait-timeout 300000`, authenticated by OIDC. The workflow's explicit immutable-tag and archive checks replace pnpm's branch-oriented Git checks for this step. Native availability waiting handles transient registry processing, including temporary E404 responses; after it succeeds, use `pnpm view <package>@<version> --json --registry <verified-registry>` to check registry identity and integrity. An availability timeout means the upload was accepted but confirmation is pending: inspect the same version before any retry, and never automatically republish it. Follow the exact tag's run to completion. A successful tag push alone is not publication. If the archive differs, inspect the build or packing cause rather than removing the guard or rewriting the release tag; any changed candidate requires a newly reviewed unused version and tag. Check current remote/registry state before retrying an ambiguous response and resume/verify the same candidate instead of blindly bumping again.

Verify remote commits/tags and registry name/version/license/bin/integrity against reviewed artifacts before installing the release on the host.

As the final delivery action, install or update the host CLI with native `pnpm add --global "<package-name>@<published-version>" --registry <verified-registry> --minimum-release-age-exclude "<package-name>@<published-version>"`, substituting the verified package identity, exact published version, and registry. The same command handles an absent CLI; do not use latest or an unpinned version. The exact-version age exclusion permits installing this just-verified release immediately while retaining the default age protection for other packages. Inspect the installed package through `pnpm list --global --json` and verify its name/version at its reported installation path. Check the host's command resolution as well as `agentscli --version`: an older installation's shim may still precede pnpm's binary directory on PATH. If installation or verification fails, report the completed publication and pending host action separately; resume the same published version without republishing or bumping it. Do not refresh project resources again through the global CLI.

Keep delivery tasks open for pending account actions, host installation, or incomplete verification. Report actual identities, checks, completed effects, and remaining actions. Add no publication engine, journal, repository rename, or rollout to other hosts or client projects.
