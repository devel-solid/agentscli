# Development

## Runtime and resources

- The private root orchestrates one public npm workspace and one lockfile. Keep its existing package/bin identity, package tags, declared Node.js lines, and dependency pins unless a required implementation change justifies an update. Never publish the root.
- The CLI exposes `init` and `update`, plus help/version. Init prepares the convention directory and installs the two product skills; update refreshes an existing installation from the running package version. Both use one installer. Agent operations belong to separately scoped skills and their deterministic scripts.
- Project generation is offline. Its real engine and complete executable closure belong to the build skill; the CLI uses its own packaged copy. Installed project scripts must run with Node.js and versioned project resources, without a global CLI, compiler, source checkout, implicit installation, Git, or network.
- Native Git is required only by operations that actually inspect or publish repositories. Use existing native authentication, argument arrays, and injected adapters. Do not collect tokens, assume a hosting vendor, execute downloaded code, or add a publication service.
- Keep the two product skill sources canonical in the package's asset templates. Builds derive complete distributed resources from those sources, independently of root installations. Install and version the root copies through the compiled checkout CLI; never edit them manually or replace them with proxies, links, or another implementation. The repository's publication skill remains local and is not distributed. Ordinary libraries and native tools are permitted dependencies; all distributed scripts and declared support files must be included.
- Generate root AGENTS.md mechanically as leading YAML frontmatter containing only `generatedBy: "@devel-solid/agentscli"`, the fixed `# AGENTS.md` title, and a deterministically ordered convention index. Derive items from convention titles and triggers with calculated links. This is the product contract, not a universal AGENTS.md requirement.
- Author final conventions directly in `.agentscli/conventions/**/*.md`, preserving their leading YAML `trigger`, H1, and body. Keep this repository's authored guidance in English; other projects choose their content's language. The build skill alone validates conventions and generates or checks the index, including an empty index when no conventions exist.
- Authored conventions, local skills, unrelated files, and Git state are protected inputs. Init and update preserve all convention and root AGENTS.md bytes, without requiring valid convention content or index ownership. Sync and check may validate conventions while preserving their bytes, including authored edits and deletions. Repeat installation replaces managed skill trees and removes obsolete skill files without merging edits.
- Recognize an existing installation from at least one product SKILL.md with its matching name, exact generatedBy package identity, and valid semantic generatorVersion. Update can recover the other missing skill or entrypoint. Init accepts missing or empty skill directories. Preserve foreign or ambiguous resource content rather than adopting it. Do not add installation manifests, markers, or configuration.
- Validate roles, inputs, paths, source integrity, and collisions before mutation. Reject unsafe symbolic links, junctions, hard links, escapes, and portable filename collisions. Preserve unmarked handwritten root instructions and unrelated paths.
- Previews and checks are write-free and use the same prospective plan as application. Replace files individually and report completed and pending effects on operational failure. Retry recomputes the same intent from current inputs.

## Verification and delivery

- Version only lightweight unit tests under each applicable `tests/unit/`. Exercise parsers, renderers, planners, and injected filesystem/Git/npm boundaries with small inputs. Do not add subprocess, CLI/Git/npm, network, installation, disposable-project, integration, or end-to-end test suites, including opt-in variants.
- Run focused units while changing behavior and root `npm run check` before reporting readiness. Keep pre-push and CI on the same gate, including read-only checks of authored conventions, the generated index, and installed resource drift. Do not format generated resources independently of their canonical installation. Treat builds, real local application, and package/archive inspection as separate delivery operations; report their actual evidence without claiming installed-package or live-provider coverage.
- After cloning, `npm ci` installs dependencies and `npm run setup` enables the native Git pre-push hook. The versioned conventions and installed skills must work before rebuilding. Dogfooding builds canonical package sources, initializes resources with the compiled checkout CLI, and synchronizes the index using the canonical build skill support. Resource checks reuse that support for read-only index validation and freshness; no duplicate generator, global CLI, or published package is required.
- Preserve repository history, unrelated edits/staging, existing tags, and immutable published identities. External delivery needs authorization from the active request; reuse authorization already given. Local readiness does not establish a remote release. Ambiguous delivery responses require inspection of the exact remote identity before retrying.
- Keep temporary work in ignored locations. Versioned resources must not depend on session artifacts, cached checkouts, local machine paths, or unshipped modules.
- Report changed files, actual checks, and remaining work. Preserve unrelated changes and the requested scope.
