# A trigger that misroutes an otherwise useful agreement

## Hypothetical context

A fictional desktop editor already has a focused agreement for application keyboard shortcuts: a shortcut invokes the same command as its visible menu item, is inactive while focus is in an editable text field, and shows its key combination beside that menu item. These choices apply when adding or changing application shortcuts. They do not govern every interface change, operating-system shortcuts, or ordinary text entry.

The exact shortcut choices in the examples are fictional; the agreement does not reserve those combinations for another application.

Compare the complete [inadequate convention](inadequate/application-shortcuts.md) and [corrected convention](corrected/application-shortcuts.md).

## What remained wrong

The body is already concrete enough to guide a shortcut change. The frontmatter, however, tells readers to load it for any interface or interaction work. A contributor adjusting an icon or text-field placeholder receives a document that cannot help that task. Repeated unnecessary activation makes the instruction index less discriminating.

The remaining decision is about discovery: when does this agreement need to be read? It is not a missing example inside the body.

## What changed and why

Only the trigger changes. It now identifies adding or changing application keyboard shortcuts, matching the body and the hypothetical agreement. The title, rule, and small scenario remain intact because they already resolve command reuse and focus behavior.

No new section, table, or richer code example would fix an activation boundary. Preserving useful prose also avoids teaching that every review must visibly rewrite the entire document.

**Transferable concept:** Review the route to a convention as well as its contents. A precise trigger connects an existing agreement to the work that needs it; enrichment is unnecessary when the actual defect is discovery.
